NL2BP

自然语言到UML蓝图转换系统
GitHub: github.com/MarkfuGod/NL2BP-Natural-Language-to-UML-Blueprints | 许可证: MIT | 技术框架: CrewAI, PlantUML
摘要. 本项目提出了一个人工智能驱动的工作流系统，用于将自然语言需求转换为标准化的UML蓝图。系统实现了两种互补的方法：单代理角色切换模式和多代理协作模式。通过具有明确角色和职责的专业化AI代理，系统自动化了从需求分析到UML图生成的整个软件开发生命周期，提供企业级的PlantUML输出和全面的工作流模板。

系统架构

双模式工作流设计
系统实现了两种不同的工作流模式，以适应不同的开发场景和复杂度级别。单代理方法利用角色切换机制，而多代理方法采用并行协作模式。

图2: 具有9个专业化代理的多代理协作工作流

代理角色规范

蓝图设计师代理配置
蓝图设计师作为工作流中的核心组件，负责使用PlantUML语法将架构设计和需求转换为可视化的UML图表。
图3: 蓝图设计师代理配置与能力
代理能力
  • 输入处理: 架构设计师和需求文档的输出
  • 图表生成: 用例图、类图、序列图、活动图、组件图、部署图
  • 质量保证: PlantUML语法验证和命名一致性
  • 输出格式: 标准化的PlantUML代码和解释性文档

工作流对比

单代理多角色
  • 7个专业化角色的顺序执行
  • 需求分析师 → 系统架构师 → 蓝图设计师 → 编码员 → 代码审查员 → 部署与调试员 → 代码评论员
  • 适用于线性开发流程
  • 资源消耗较低
  • 简化的调试和控制
多代理协作
  • 9个专业化代理的并行执行
  • 系统设计、需求分析、蓝图设计、前后端设计、版本控制、敏捷看板、反馈规划、人类协作者
  • 适用于复杂的敏捷开发
  • 实时进度监控
  • 智能版本管理

实现框架

CrewAI集成
多代理系统使用CrewAI框架实现，提供结构化的代理定义、任务编排和代理间通信机制。
# 代理定义示例 from crewai import Agent, Task, Crew requirements_agent = Agent( role='需求分析师', goal='分析和细化用户需求，创建优先级需求列表', backstory='经验丰富的需求分析师，擅长将模糊的用户需求转化为清晰的功能规格', verbose=True ) # 任务定义 requirements_task = Task( description='分析用户需求并生成结构化需求文档', agent=requirements_agent )
PlantUML图表生成
系统生成标准化的PlantUML图表，具有全面的语法验证和命名规范。每个图表都包含详细的解释，并遵循企业级格式标准。

总结

NL2BP系统代表了AI驱动软件工程自动化的重大进步。通过结合单代理角色切换和多代理协作模式，系统提供了将自然语言需求转换为标准化UML蓝图的全面解决方案。该实现展示了在企业环境中的实际应用性，同时为AI在软件工程中应用的学术理解做出了贡献。项目的开源性质使这一新兴领域的进一步研究和开发成为可能。
