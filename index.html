Being-H0.5 — reproducing a frontier VLA model, and testing what pre-training buys

MSc project at HKU, supervised by Prof. Taku Komura · 2025 – 2026

The first stage was reproduction. I brought the released codebase up from a fresh clone on a rented GPU server: the ZeroMQ inference server, the LIBERO benchmark under MuJoCo with headless EGL rendering, and later RoboCasa v0.2 with its pinned mujoco and numpy versions and mirrored assets. The released code had a few breakages along the way (an endpoint registered with the wrong signature, a missing modality_config method, float64 states crashing the server-side transforms), which I fixed and wrote up as an upstream patch. With the chain working, I evaluated the official 2B LIBERO checkpoint over 2,000 episodes: 98.6% on spatial, 97.0% on object, 98.0% on goal, and 95.0% on libero-10, in line with the paper.

The second stage was recreating post-training from base weights, without touching the released checkpoint. That meant a full fine-tune of InternVL3.5-4B (Qwen3-4B language backbone) with a Qwen3-4B action expert in the mixture-of-transformers layout and a flow-matching action head, on 4 GPUs with FSDP and gradient checkpointing. I wrote the launch scripts and runbooks myself, including auto-resume and checkpoint-saving policies, because rented instances can be stopped at any moment and an unsaved run is a lost run. I learned that one the hard way, once.

Midway through, the server moved to 4× RTX PRO 6000 Blackwell cards (compute capability sm_120), which the stock environment could not use at all. I migrated the stack to PyTorch 2.8 with CUDA 12.8 and changed five places in the model and training code to make it run on the new architecture: flash-attn became optional, attention switched to SDPA, the packed Qwen3 model got a gradient-checkpointing implementation it never had, flex-attention kernels got smaller block sizes to fit Blackwell's smaller shared memory, and a missing set_device call that put every rank on GPU 0 was fixed. After that, 4-card FSDP training ran stably at about 0.3 steps/s with roughly 92 GB in use per card.

The experiment I care most about came last. I wanted to test whether a larger backbone can make up for skipping the original human-centric pre-training, so I trained the 4B model from base weights and compared it with the official pre-trained 2B checkpoint. At 6k steps the from-base 4B reached 37.8% on LIBERO spatial; the pre-trained 2B sits at 95–98.6%. Doubling the parameters did not close the gap. My reading is that post-training alone cannot substitute for the pre-training stage, and I proposed follow-ups to separate the two effects cleanly: moving the comparison to RoboCasa, where scores are far from saturated, and measuring data-efficiency curves instead of a single end point. That RoboCasa run is in progress now.

On the side I also built a small proof of concept with Gemma-4-E2B as a frozen backbone plus a trained state encoder and action head. It settled two questions quickly: a prompt-only VLM is not a robot policy, and a small bolted-on action head is not enough either.

Skillios (ItsMyGoal) — an iOS goal planner with an agent inside

Personal project · 2025 – 2026 · TestFlight beta

ItsMyGoal is a gamified goal planner. You give it a goal, an agent decomposes it into a skill tree of quests with prerequisites and XP, and the app tracks your todos, routines, and character progress on top. There is also a chat agent that plans real-world activities: it checks the weather, searches places, gets directions, and produces an itinerary that you confirm before anything is saved.

I built the whole product. The iOS client is SwiftUI with SwiftData as the source of truth. The agent loop runs on the device: it talks to an OpenAI-compatible model, handles tool calls across about ten tools (tree generation, quest management, todos and routines, weather, place search, directions), and runs read-only tools concurrently while keeping database-mutating tools serial. AI-created tasks always go through a confirmation sheet before they touch the database, and confirmed tasks can sync to Apple Calendar through EventKit.

The backend is FastAPI with SQLAlchemy on PostgreSQL. It handles email-code and Sign-in-with-Apple auth, snapshot sync of user data, and an LLM proxy with per-user daily quotas so new users do not need their own API key. Google Maps and weather calls go through server-side proxies, which keeps third-party keys out of the app. Everything is deployed on AWS through CDK: VPC, ALB, ECS Fargate, RDS, and Secrets Manager, with a separate migration task for schema changes.

The part that took the most discipline was keeping the plan JSON schema stable between Swift and Python, since two generation paths share it and either side can drift quietly. Those contracts are pinned by XCTest on the iOS side and pytest on the backend.

KithAgent — a local memory layer for agents

Personal project · 2025 – 2026

Kith comes from a daily annoyance: tools like Cursor and Claude Code forget who you are between sessions, while the context that actually describes you lives in files on your machine. Kith is a memory system that runs locally. You choose which folders it may scan; it indexes them, asks an LLM to triage every file into high, medium, low, or skip, and then spends its summarization budget by priority. Files that reveal your projects and preferences get understood first; caches, build artifacts, and vendor code get skipped instead of wasting tokens.

The daemon watches whether you are active and schedules its own background work, so the heavy summarization runs while you are away from the machine. Memory lives in a local SQLite store under ~/.agent_sys, and retrieval is hybrid: exact file lookup when you know what you want, RAG when you do not. Everything is exposed through a local syscall API over Unix socket and HTTP with token auth, plus a Python client SDK, so any agent can ask what you have been working on and what matters now. I also wrote Cursor and Claude Code skills that plug into it, a web dashboard for triage and RAG control, and an Electron companion app.

It works with local Ollama models or any OpenAI-compatible or Anthropic API. Nothing leaves the machine except the model calls you configure, and the optional browser ingestion reads only titles and bookmarks, never cookies, sessions, or passwords.

Atari Portal — nine arcade games joined by a portal

Personal project · 2025 · play in browser

A retro arcade collection where nine classic-style games (Pac-Man, Breakout, Space Invaders, Frogger, Asteroids, Tetris, and three originals) connect through a portal system. Each game has its own trigger condition; meet it and a portal opens that warps you into the next game. On top of that sit story, arcade, and free-play modes, a coin economy with a small shop, a speed-boost mechanic for scoring streaks, and a global difficulty curve that climbs with every traversal.

Gameplay runs on Phaser 3, and the portal and glitch effects run on a Three.js overlay above it. Every texture is drawn with the Canvas API at boot and every sound is synthesized with the Web Audio API at runtime, so the build ships with no image or audio files at all. It deploys to GitHub Pages through GitHub Actions and also packages as an Electron desktop app for Windows and macOS.
